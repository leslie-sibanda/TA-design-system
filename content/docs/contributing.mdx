---
title: Contributing
description: Bring evidence, preserve shared contracts and make changes reviewable.
---

## Propose a change

Describe the user need and check existing components. Decide whether the change belongs in shared UI, a theme or an application.

## Implement with tests

Write a failing behaviour test, implement the smallest passing change and repeat. Keep canonical source, examples, documentation and metadata consistent.

## Verify before release

Run types, lint, unit tests, static-export checks and browser/accessibility tests. Review keyboard behaviour and responsive layouts. Do not mark a proposal as released before its contract and implementation are verified.
